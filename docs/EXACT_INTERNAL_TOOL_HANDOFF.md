Alif Jakir · 20 November 2026

## Repository baseline

`release/wasm-replay-v0.1` at `803772e` is the shareable checkpoint release candidate. The maintained entry point is `visuaml-client/voxel-replay/tools/visuaml_replay.py`. The validated loader, call-frame state and single-step graph live in `backend/visuaml/compiler_lab/frozen_calls_v58.py`; ordinary graph operations, memory and the fuel state live in `frozen_recurrent_v58.py`. The graph owns instruction effects. The host supplies the validated image and initial conditions, drives execution, and publishes the trace. The archived compiled CPU runner is a separate execution path and the source-step graph supplies the release's reference semantics.

The input-prefix search, live continuation, and original-boundary comparison sit above that contract. Their output can be used to diagnose a lowering that agrees at exit and differs inside a region. A new execution substrate should emit an equivalent ordered boundary stream. For a different instruction set, document the mapping and compare instruction-level state to a separate logical reference before comparing guest-visible outputs with WASM.

## Local evidence and next verification gates

The internal-tool artifact is a bounded recurrent hard-attention prototype. Its learned component classifies structured token inputs and routes operands. It exercises one forward graph with causal interventions, using an unseen program image. The exact core uses explicit integer tensors and hard addressed reads. It has neither an automatic graph-to-weights lowering nor a conventional causal softmax-only transformer executing the whole VM. The local benchmark compares matched arithmetic results with Python, the VisuaML source graph and Wasmtime. It cannot establish external engine parity.

1. Align specialized trace semantics on the reproduced loop and repeat across changed input values. Use the exact graph evaluator and C++ inference as additional baselines.
2. Synthesize a portable exact instruction circuit from a typed graph into explicit transformer projections and FFN weights. Freeze it before authoring a second program. Compare every boundary and include an overwritten address and an out-of-range case.
3. Compare dense hard attention, append-only history retrieval, and indexed mutable memory at increasing address space and history sizes. Hold the logical execution constant and report precision, bytes touched, and measurement boundaries.
4. Move from positional token routing to an independently trained language controller. Check unseen programs, rejected operands, execution-disabled and result-perturbation cases. Compare against a conventional external exact tool and pinned Meridian weights once accessible.

## Synthesized executor follow-up

The first affine/ReLU lowering and fixed Q/K/V hard-attention projections are now archived with a recurrent-state executor. It runs an independent program authored after freeze, matches every logical boundary against a scalar oracle, matches ordered stores against the frozen WASM graph, and passes learned-router output interventions. This closes the bounded hard-attention synthesis gate. A conventional causal transformer lowering and free-form tool selection remain separate research gates.
