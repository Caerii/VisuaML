# Tool acquisition interface

The model receives three registry descriptions as text in the form `name does family .`. The frozen vocabulary has six possible names and the family words `offset`, `boost`, and `trim`. Registry entries may appear in any text order. Each name token also binds to exactly one row in a parallel registry tensor. That tensor can use a different order from the text. Those rows contain the program image, role, and fuel allowance. Duplicate names are rejected at request lookup.

The argument schema is two integers. The first is a word in 0–31. The second is a repeat count of 1–9, restricted to 1 for the offset role. Each image uses the validated hard-attention interpreter profile. A tool reports an integer in 0–31 or an explicit unavailable, invalid, or exhausted status. The interpreter starts each accepted call with private memory and has an upper bound of 48 cycles. An override changes the first reported value after exact execution, leaving the computed value and trace intact.

Training saw the three family descriptions and the controlled conditional template with threshold 12. It shuffled names and description order on individual examples. The 5,904 transcripts carry synthetic feedback and answers independently generated from the prompt. Zero-repeat, unavailable, and exhausted feedback were included. Seed and repeat pairs satisfying `(3 * seed + repeat) % 7 == 0` were excluded. Evaluation can introduce new executable programs and runtime results for those families. The interface does not imply support for unseen vocabulary, arbitrary schemas, novel semantic families, or open-ended English.
